## 1. 背景与目标

### 1.1 背景

2026 年美加墨世界杯临近，用户对赛前信息的需求集中在：赛程、球队/球员状态、预测市场隐含概率，以及不同玩法（胜平负、比分、让球胜平负）下的决策参考。现有信息分散在新闻站、数据站、Polymarket 等平台，用户难以形成可解释、可追溯的综合判断。

### 1.2 产品目标

构建一个以**世界杯赛程**为入口的智能分析平台：针对每场比赛，通过**多角色 AI 战术室合议**（充分讨论直至达成共识），结合基本面、技术面与预测市场数据，输出三种玩法的结构化推荐及与市场价格的偏差分析。

### 1.3 成功标准（上线后 3 个月内）

| 指标 | 目标 |
|------|------|
| 单场合议任务完成率 | ≥ 90% |
| 合议结论 Schema 校验通过率 | ≥ 95% |
| 详情页「完整战术室」平均阅读时长 | ≥ 3 分钟 |
| 用户对共识结论满意度（👍/👎） | 👍 ≥ 60% |
| 热门场次预生成覆盖率 | 开赛前 24h 内 Top 20 场次 |

### 1.4 非目标（明确不做）

- 用户注册体系、账户资产、充值提现（一期不做）
- 对接博彩公司下单、代客投注、跟单
- 承诺盈利或提供投资建议资质
- 实时比分直播、视频转播

## 2. 产品定位

### 2.1 一句话描述

**以赛程为入口的 AI 战术室：多角色充分合议，对每场比赛给出可解释、可回放、达成共识的胜平负 / 比分 / 让球推荐，并对照预测市场隐含概率。**

### 2.2 价值主张

| 用户痛点 | 产品能力 |
|----------|----------|
| 信息分散 | 基本面 + 技术面 + 预测市场一屏聚合 |
| 不懂如何权衡 | 7 角色多轮辩论，分歧可见 |
| 不相信黑盒结论 | 完整讨论实录可回放，结论带论点编号 |
| 多种玩法不会选 | 分玩法合议，输出结构化推荐表 |
| 想知道「值不值」 | 共识概率 vs 市场隐含概率（Edge）对照 |

### 2.3 合规定位

产品定位为**赛事研究与信息分析工具**，全站展示免责声明：

> 本平台内容由 AI 基于公开信息生成，仅供参考，不构成任何投资建议或投注建议。请遵守所在地法律法规，理性看待预测结果。

不在产品内引导用户至博彩或交易下单页面。

## 3. 目标用户

| 用户类型 | 特征 | 核心场景 |
|----------|------|----------|
| 轻度球迷 | 关注热门场次 | 开赛前快速查看共识结论与核心理由 |
| 数据爱好者 | 习惯看数据与赔率 | 对比 Agent 共识概率与市场概率 |
| 玩法研究者 | 关注让球、比分 | 展开「玩法分拆」阶段讨论，查看少数意见 |
| 内容消费者 | 愿意阅读长分析 | 完整回放 10–30 分钟级战术室讨论 |

## 4. 功能范围

### 4.1 功能总览

```
赛程首页 → 比赛详情
              ├── 数据概览（基本面 + 技术面）
              ├── 预测市场（Polymarket 等）
              └── AI 战术室（多 Agent 合议 · 核心）
                      ├── 讨论实录（群聊时间线）
                      ├── 分歧雷达 / 论点索引
                      └── 共识结论（三玩法 + Edge）
```

### 4.2 赛程首页

**描述**：展示 2026 美加墨世界杯赛程列表，作为全站唯一入口。

| 需求 ID | 需求描述 | 优先级 |
|---------|----------|--------|
| F-001 | 按日期、小组、阶段（小组赛/淘汰赛）筛选赛程 | P0 |
| F-002 | 卡片展示：开球时间、主客队、国旗/队徽、比赛状态（未开始/进行中/已结束） | P0 |
| F-003 | 点击进入比赛详情；已结束比赛可查看历史合议 | P0 |
| F-004 | 标记「已有共识」「合议生成中」「未分析」状态 | P1 |
| F-005 | 热门场次置顶（按关注度/淘汰赛阶段配置） | P2 |

**数据来源**：官方赛程种子数据 + 足球数据 API 同步（一期可静态 JSON，二期 API 自动更新）。

### 4.3 比赛详情 — 数据概览

**描述**：为 Agent 合议与用户阅读提供结构化事实底座。

| 需求 ID | 需求描述 | 优先级 |
|---------|----------|--------|
| F-101 | 展示双方近期战绩（近 5–10 场）、进失球 | P0 |
| F-102 | 展示交锋历史（若有） | P1 |
| F-103 | 关键球员列表：位置、状态标签（健康/疑伤/缺阵） | P0 |
| F-104 | 技术面指标：近况趋势、主客场差异、对强弱队进球分布、简易实力评分（Elo/Power Rating 二选一） | P1 |
| F-105 | 每条事实带来源标识（`evidence_id`），供讨论引用 | P0 |
| F-106 | 新闻/情报摘要（RSS + LLM 摘要，标注来源与时间） | P2 |

**说明**：产品内「技术面」指足球竞技统计趋势，与股票技术分析无关。

### 4.4 比赛详情 — 预测市场

**描述**：接入公开预测市场，提供隐含概率与流动性信息（若可得）。

| 需求 ID | 需求描述 | 优先级 |
|---------|----------|--------|
| F-201 | 接入 Polymarket：映射到对应比赛/结果合约，展示隐含概率 | P0 |
| F-202 | 运营维护 `match_id ↔ polymarket_event_slug` 映射表 | P0 |
| F-203 | 展示共识概率 vs 市场概率及 Edge（共识 − 市场） | P0 |
| F-204 | 接入 Robinhood 预测市场 | P2（API 不可用则展示「即将支持」） |
| F-205 | 成交量/价差趋势（数据可得时） | P2 |

### 4.5 比赛详情 — AI 战术室（核心）

**描述**：7 个固定角色进行多轮结构化讨论，直至满足共识结束条件，输出可校验的结论与完整实录。

#### 4.5.1 角色编制

| 角色 ID | 名称 | 职责 |
|---------|------|------|
| `data` | 数据官 | 量化战绩、进失球、对阵历史；禁止无来源断言 |
| `squad` | 阵容官 | 战术风格、关键球员、伤病与不确定性 |
| `market` | 市场官 | 解读预测市场隐含概率，质疑 Agent 与市场的偏差 |
| `skeptic` | 风控官 | 专门唱反调；合议结束前须 ACK 或保留意见签字 |
| `handicap` | 让球专家 | 让球盘逻辑、诱盘与实力盘分析 |
| `scoreline` | 比分专家 | 进球环境、比分分布，与 1x2 交叉验证 |
| `moderator` | 主持人 | 控场、归纳分歧、发起表决、发布共识文书 |

#### 4.5.2 讨论协议

消息类型（前端按类型渲染样式）：

| 类型 | 说明 |
|------|------|
| `STATEMENT` | 陈述观点，须附 `evidence_ids`（若有事实主张） |
| `CHALLENGE` | 质疑他人，须 `@角色` 并引用论点编号 |
| `REBUTTAL` | 反驳 |
| `REVISE` | 修正己方先前观点 |
| `SUPPORT` | 支持，须引用对方论点编号 |
| `QUESTION` | 提问 |
| `VOTE` | 表决（仅主持人宣布表决轮后） |
| `ACK` / `ACK_WITH_RESERVATION` | 风控官对最终共识签字 |
| `CONSENSUS_DRAFT` / `CONSENSUS_FINAL` | 共识草案 / 终稿 |
| `THREAD_DIGEST` | 主持人每 N 轮阶段摘要（不替代原文） |

#### 4.5.3 讨论阶段

| 阶段 | 行为 | 说明 |
|------|------|------|
| Opening | 7 角色各自提交 Opening Brief | 可长篇展开，并行生成 |
| CrossExam | 针对 Opening 逐条 `CHALLENGE` 与回应 | 至少 3 轮，直至无新 Challenge 或进入 DeepDive |
| DeepDive | 对核心争议点往复交锋 | 主要消耗轮次，**不设 Token 上限** |
| PlaybookSplit | 按玩法分拆：胜平负 / 比分 / 让球 | 各玩法独立争论后出草案 |
| FinalVote | 各玩法投票 + 提交概率区间 | 见表决规则 |
| Consensus | 主持人发布 `CONSENSUS_FINAL`，风控官签字 | 输出结构化 JSON |

**轮次**：不设 Token 限制；设 `max_rounds = 30` 防止死循环。达到上限仍未共识时，输出 `PARTIAL_CONSENSUS`（部分共识），列明未决议题，**禁止伪造一致**。

#### 4.5.4 共识结束条件（须同时满足）

1. 连续 **2 轮** 无人发起 `CHALLENGE`
2. 主持人发布 `CONSENSUS_FINAL`，且风控官 `ACK` 或 `ACK_WITH_RESERVATION`
3. 结论 JSON 通过 Schema 校验
4. L1 事实层：无可核验的事实反驳未决

#### 4.5.5 表决与置信度

| 情形 | 规则 | 前端展示 |
|------|------|----------|
| 强共识 | ≥ 5/7 角色 `VOTE` 同一选项 | 正常置信度 |
| 弱共识 | 4/7 一致 | 标注「分裂共识」+ 少数意见摘要 |
| 无共识 | 未达 4/7 | 该玩法 `abstain`（不建议给出方向） |

置信度：各角色提交 `(pick, p_low, p_high)`，取**中位数**为展示概率，区间宽度映射为「分歧度」（宽则 UI 警告）。

#### 4.5.6 功能需求列表

| 需求 ID | 需求描述 | 优先级 |
|---------|----------|--------|
| F-301 | 用户进入详情可触发合议；热门场开赛前自动预生成 | P0 |
| F-302 | SSE 流式推送讨论消息，展示阶段进度（如 CrossExam 第 5 轮） | P0 |
| F-303 | 讨论按阶段折叠：Opening / 交叉盘问 / 深度讨论 / 玩法分拆 / 表决 / 共识 | P0 |
| F-304 | 论点编号（如 `E-012`），结论理由可点击跳转至原文 | P1 |
| F-305 | 分歧雷达：1x2、比分、让球、市场偏差四维度争议热度 | P1 |
| F-306 | 阅读模式：只看共识 / 完整战术室 / 只看分歧 | P1 |
| F-307 | 共识证书卡：签字角色、时间、是否保留意见 | P0 |
| F-308 | 合议完成结果持久化，支持链接回放 | P0 |
| F-309 | 无 evidence 的 STATEMENT 由规则引擎打回重写 | P1 |
| F-310 | 每 5 轮主持人自动生成 `THREAD_DIGEST` | P2 |

### 4.6 共识结论输出

**描述**：合议结束后，用户获得结构化交付物。

| 需求 ID | 需求描述 | 优先级 |
|---------|----------|--------|
| F-401 | **胜平负**：推荐结果、置信度、核心理由（≤3 条，带论点链接） | P0 |
| F-402 | **比分**：Top3 比分及置信度 | P0 |
| F-403 | **让球胜平负**：盘口线、推荐方向、置信度、理由 | P0 |
| F-404 | **市场 Edge 表**：各结果共识概率 vs 市场隐含概率及排序 | P0 |
| F-405 | **少数意见**：未投多数派的角色摘要，永久保留 | P0 |
| F-406 | **未决议题**：部分共识时列出（如伤病未确认） | P0 |
| F-407 | 导出/share 共识证书图（二期） | P2 |

**「最赚钱」表述规范**：产品内统一为 **「相对市场预期偏差最大（Edge）」**，并附 Skeptic 保留意见中的风险说明；禁止使用「稳赚」「必买」等用语。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 幻觉 | 错误伤病/战绩 | 无 `evidence_id` 的事实陈述打回；数据官仅引用结构化事实 |
| 市场映射错误 | Edge 误导 | 人工映射表 + 映射审核状态展示 |
| 合议死循环 | 任务永不结束 | max_rounds=30 → PARTIAL_CONSENSUS |
| 合规 | 博彩关联风险 | 免责声明；无下单；用语规范 |
| 讨论过长用户流失 | 跳出率高 | 默认「只看共识」；完整讨论可选 |

## 12. 验收标准（P1 MVP）

- [ ] 赛程首页可浏览全部种子场次并进入详情
- [ ] 至少 1 场真实（或准真实）比赛跑通 7 角色全流程合议并产出 `CONSENSUS_FINAL`
- [ ] 讨论实录可按阶段折叠回放，SSE 流式可见
- [ ] 结论含胜平负、比分 Top3、让球三项及市场 Edge 表
- [ ] Polymarket 至少 1 个场次映射成功并展示市场概率
- [ ] 风控官保留意见路径可触发且 UI 可见
- [ ] 达到 max_rounds 时输出 PARTIAL_CONSENSUS，不输出假共识
- [ ] 全站免责声明可见

## 13. 附录

### 13.1 原始产品想法（归档）

1. 美加墨世界杯预测平台，玩法：胜平负、比分、让球胜平负  
2. 互联网获取球队/球员基本面；Polymarket、Robinhood 获取预测市场数据  
3. 多 Agent 根据数据综合分析，推荐相对市场更有价值的选项  
4. 首页赛程列表 → 详情页 Agent 群聊式讨论 → 讨论可见 → 最终共识结果
